# ADR 0019: Filesystem Boundary Containment and Pre-Execution Permissions Pipeline

## Status
Accepted

## Date
2026-09-27

## Context
Autonomous agents interact directly with the host machine through tools such as `exec_bash`, `write_file`, and `replace_file`. Without explicit boundary controls:
1. **Workspace Traversal**: An agent may unintentionally or maliciously traverse outside its designated project workspace into parent folders, system configurations (`/etc`), or operator home directories.
2. **Credential Exposure**: Unrestricted access risks reading or overwriting sensitive authentication stores (e.g. `~/.ssh`, `~/.aws`, `~/.gnupg`, or global shell profiles).
3. **Destructive Shell Commands**: Commands generated by LLMs may contain destructive actions (`rm -rf /`, raw disk writes via `dd`, `mkfs`, or privilege escalation attempts via `sudo`).
4. **Unsupervised Execution in YOLO Mode**: When operators engage auto-approval, out-of-bounds actions could execute silently without human oversight.

We require a deterministic, pre-execution permissions pipeline that guarantees project workspace isolation and intercepts hazardous operations before execution.

## Decision
We enforce a **pre-execution permissions verification pipeline** across all agent runtimes (`lokol exec`, `lk`, and `liblokol`):

```mermaid
flowchart TD
    CandidateAction["Candidate Tool Action"] --> PathContainment{"Canonical Path Containment Check"}
    PathContainment -->|Path Escapes Workspace Root| BlockOOB["BLOCK: Filesystem Boundary Violation"]
    PathContainment -->|Path Within Workspace| ShellAnalysis{"Static Shell Risk Analysis"}
    ShellAnalysis -->|Critical Hazard (rm -rf /, mkfs, dd)| BlockHazard["BLOCK: Destructive Operation"]
    ShellAnalysis -->|High Risk (sudo, curl | bash, ~/.ssh)| WarnRisk["WARN: Security Risk Flagged"]
    ShellAnalysis -->|Safe Operation| AuthorizeAction["Authorize Execution"]
```

### 1. Canonical Path Containment
All file-mutating and file-reading tools (`write_file`, `replace_file`, `read_window`, `read_outline`) undergo canonical path resolution:
- Resolves symlinks and relative path sequences (`..`) using physical path evaluation.
- Verifies that the canonical target path is strictly contained within the active project workspace root.
- Rejects paths targeting sensitive directories (`/etc`, `~/.ssh`, `~/.aws`) or parent directory traversal attempts.

### 2. Deterministic Shell Risk Inspection
`exec_bash` commands are statically inspected prior to process spawning:
- **Critical Risk (Automatic Block)**: Root-level recursive deletions (`rm -rf /`), partition formatting (`mkfs`, `fdisk`), raw block device writes, and fork bombs.
- **High Risk (Security Warning)**: Privilege escalation (`sudo`, `su`, `doas`), piping untrusted network payloads to shell interpreters (`curl ... | sh`), and access attempts to credential files.

### 3. Runtime Enforcement Modes
- **Autonomous Headless (`lokol exec`)**: Blocked actions are immediately refused. The runner injects a structured denial feedback message (`<action_result>[PERMISSION DENIED]: ...</action_result>`), enabling the model to recover and self-correct without crashing the session.
- **Interactive TUI (`lk`)**:
  - Flagged actions display a prominent `⚠️ SECURITY WARNING: <Reason>` in the confirmation modal.
  - **YOLO Mode Safety Intercept**: If an action is flagged as out-of-bounds or hazardous, autonomous auto-approval automatically pauses and requires explicit human confirmation.

## Consequences

### Positive
- **Guaranteed Workspace Isolation**: Confines agent filesystem mutations strictly to the authorized directory.
- **Host Protection**: Protects critical system files, disks, and credentials from accidental or adversarial compromise.
- **Zero Latency**: Pure Go deterministic boundary checks execute in `< 1ms` with zero external runtime dependencies.
- **Resilient Autonomous Self-Correction**: Transparent denial messages allow the agent to correct mistaken paths without halting the autonomous loop.

### Negative / Trade-offs
- Legitimate commands requiring symlink navigation outside the repository root require explicit operator approval in interactive mode.
